# Church Podcast Automation

Weekly sermon automation — CLI tool + native macOS app, sharing the same Python backend.

---

## Project Structure

```
ChurchPodcast/
├── setup.sh                          ← Run this once (installs everything)
├── run.sh                            ← Generated by setup.sh — CLI launcher
├── .venv/                            ← Python venv created by setup.sh
│
├── python-server/
│   ├── server.py                     ← Flask API + SSE server (used by the Mac app)
│   ├── church_podcast_automation.py  ← Original CLI tool (used by run.sh)
│   └── requirements.txt             ← Shared Python dependencies
│
├── ChurchPodcast.xcodeproj/         ← Open this in Xcode
└── ChurchPodcast/
    ├── ChurchPodcastApp.swift        ← App entry point (starts Flask server)
    ├── ChurchPodcast.entitlements
    ├── Views/                        ← SwiftUI wizard screens
    │   ├── ContentView.swift         ← Router + step indicator
    │   ├── Components.swift          ← Shared UI components
    │   ├── WelcomeView.swift
    │   ├── SourceView.swift
    │   ├── TimestampsView.swift
    │   ├── MetadataView.swift
    │   ├── ProcessingView.swift
    │   ├── UploadView.swift
    │   ├── DoneView.swift
    │   └── CleanView.swift
    ├── ViewModels/
    │   └── PipelineViewModel.swift   ← Wizard state machine
    └── Services/
        ├── APIService.swift          ← HTTP calls to Flask server
        ├── SSEListener.swift         ← Parses real-time progress events
        └── ServerManager.swift      ← Starts/stops python-server/server.py
```

**Data files** (created at runtime, not in git):
```
client_secrets.json       ← You add this (YouTube API credentials)
youtube_token.json        ← Auto-generated after first YouTube login
podcast_output/           ← Trimmed video + MP3 saved here
inbox/                    ← Drop .mp4 files here for Manual mode
```

## One-Time Setup

```bash
chmod +x setup.sh
./setup.sh
```

This installs Homebrew (if needed), Python 3.12, ffmpeg, and all Python packages into `.venv`. It also generates `run.sh` for CLI use.

**Requirements:** macOS 13 Ventura or later. Internet connection for the first run.

---

## Using the CLI

Every Monday:

```bash
./run.sh
```

Interactive menus walk you through the full workflow. You can also pass flags to skip menus:

```bash
./run.sh --mode A --url "https://youtube.com/watch?v=..." --start 00:32:15 --end 01:18:40
./run.sh --mode B --file ~/Downloads/service.mp4 --start 00:15:00 --end 01:05:00
./run.sh --mode A --latest   # auto-fetch latest video from your channel
```

See `church_podcast_automation.py` CONFIG block for channel ID and defaults.

## Using the Mac App

### First build

1. Run `./setup.sh` first (creates `.venv` — required before building)
2. Add your `client_secrets.json` to this folder (see YouTube API Setup below)
3. Open `ChurchPodcast.xcodeproj` in Xcode
4. Select your Team in Signing & Capabilities
5. Press **⌘R**

### How it works

The app automatically starts `python-server/server.py` using `.venv/bin/python` when it launches. The Flask server runs on `localhost:5001`. Progress from ffmpeg and yt-dlp is streamed back to the app in real time via Server-Sent Events.

### Bundling for distribution

When you archive the app (Product → Archive), Xcode copies `python-server/` and `.venv/` into `ChurchPodcast.app/Contents/Resources/` automatically via the "Embed Python Resources" build phase. The bundled app is fully self-contained and works on any Mac with macOS 13+.

> **Note on .venv size:** The `.venv` folder can be 100–300 MB. This is normal — it contains yt-dlp, google-api-python-client, and Flask. The app bundle will be large but self-contained.

## YouTube API Setup

Required for uploading to YouTube (both CLI and app). One-time setup.

1. Go to [console.cloud.google.com](https://console.cloud.google.com)
2. Create a project → Enable **YouTube Data API v3**
3. Create credentials → OAuth 2.0 Client ID → Desktop app
4. Download JSON → rename to `client_secrets.json` → place in this folder
5. First upload opens a browser to log in. After that, `youtube_token.json` is saved automatically.

## How the CLI and App share code

The CLI (`church_podcast_automation.py`) and the Flask server (`server.py`) are independent programs that share the same CONFIG values and data directories. Both use the same `.venv`. Changes to CONFIG in `church_podcast_automation.py` should be mirrored in `server.py`.

| Feature | CLI (`run.sh`) | App |
|---|---|---|
| Download from YouTube | ✓ | ✓ |
| Auto-detect timestamps | ✓ | ✓ |
| Trim + normalize | ✓ | ✓ |
| Export MP3 | ✓ | ✓ |
| Upload to YouTube | ✓ | ✓ |
| Open Spotify | ✓ | ✓ |
| Clean files | ✓ | ✓ |
| Live progress bars | tqdm in terminal | SwiftUI progress bars |

## Troubleshooting

| Problem | Solution |
|---|---|
| "Backend error" on app launch | Run `setup.sh` first; check `.venv` exists |
| App can't find `.venv` | `ServerManager.swift` walks up from the bundle — keep the project folder intact |
| Download fails | Log into YouTube in Chrome/Safari/Firefox; grant Full Disk Access to the app in System Settings |
| Upload goes to wrong channel | Delete `youtube_token.json` and re-run to re-authenticate |
| Audio too quiet | Lower `loudness_target` to `-12` or `-10` in both `server.py` and `church_podcast_automation.py` |
| Xcode "file not found" for `.venv` | Run `setup.sh` before building — Xcode needs `.venv` to exist to copy it into the bundle |
